# Third-party components and generated evidence

The licence for the original repository code and synthetic fixtures is still awaiting an explicit maintainer decision. This file does not select it or apply a third-party licence to the project.

The original [dbt parse manifest](evidence/2026-11-13/dbt-parse-manifest.json), the [executed PostgreSQL build](evidence/2026-11-14/native-flow/dbt/build/manifest.json), the [restored-database manifest](evidence/2026-11-14/native-flow/dbt/restored-test/manifest.json), and the later [CI-control build](evidence/2026-11-14/ci-evidence-hardening/dbt/build/manifest.json) and [documentation manifest](evidence/2026-11-14/ci-evidence-hardening/dbt/docs/manifest.json) include macro definitions from installed dbt packages as part of dbt's generated output. The new 15 November [build](evidence/2026-11-15/dependency-qualification/native-flow/dbt/build/manifest.json), [documentation](evidence/2026-11-15/dependency-qualification/native-flow/dbt/docs/manifest.json) and [restored-database](evidence/2026-11-15/dependency-qualification/native-flow/dbt/restored/manifest.json) manifests contain the same category of upstream material. Those definitions retain their upstream rights and copyright notices. Copies of the actual installed licence files are preserved separately:

The [source inventory](evidence/third-party-licenses/sources.json) records package versions, installed source paths and file digests. These copies include the Apache License 2.0 text and dbt Labs copyright notice supplied by the packages. The 14 and 15 November qualifications used the same versions of these dbt packages; the application dependency refresh did not replace their rights. Macro source and compiled output derived from those packages have not been relabelled as project-authored code. Generated dbt application HTML, PostgreSQL/browser binaries and the database backup archive are not vendored with the evidence.

The [current installed component inventory](evidence/2026-11-15/dependency-qualification/native-flow/components.json) records the updated Python dependencies, their publisher declarations and available licence files. The [13 November inventory](evidence/2026-11-13/components.json) remains a historical record of the earlier 119-dependency environment. It keeps distribution-obligation review items visible, including the PostgreSQL driver packages; a successful metadata check is not a licensing certification. The locked requirements do not change those components' licences.

The FastAPI 0.162.4, Pydantic 2.14.3 and Hatchling 1.33.0 update retains the upstream rights described by the [dependency-review sources](evidence/2026-11-15/dependency-qualification/dependency-review/). The application/development lock and seven hashed build constraints are dependency controls, not project licence grants. Build tools and their downloaded distributions are not vendored with the evidence. The installed-package audit covers 119 application, development and qualification packages; the separate build audit covers seven explicitly constrained dependencies, some of which overlap that inventory. These dated vulnerability audits do not certify licensing or remove distribution obligations.

Terraform CLI 1.17.2 is a qualification tool under its upstream BUSL-1.1 terms; the Snowflake provider 2.22.1 declares MIT and the pinned setup action declares MPL-2.0. Their binaries are not vendored in this repository. Container/OS layers and any later distribution of built images require their own reviewed inventory. Upstream references are recorded in the Terraform workflow and operating documentation.
